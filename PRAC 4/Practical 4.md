### Capture and analyze network packets using Wireshark


---

## Aim
> To capture and analyze network packets using Wireshark.

## Requirements
- Computer or laptop
- Wireshark
- Internet or Wi-Fi connection
- A `.pcap` or `.pcapng` capture file

## What is Wireshark?
Wireshark is a network protocol analyzer. It can capture traffic from a network interface or open a saved packet-capture file, then display packets and their protocol details. The filter bar in this practical uses **display filters**: they control which captured packets are shown and do not remove other packets from the capture file.

## Procedure

### Capture packets
1. Open Wireshark and select the active network interface.
2. Start the capture and generate a small amount of test traffic, such as opening a website or pinging a host.
3. Stop the capture and save it as `.pcapng` or `.pcap`.

### Open a capture file
1. Select **File → Open** and choose a `.pcap` or `.pcapng` file.
2. Enter the display filter in the filter bar and press **Enter**.
3. Clear the filter to display all packets again.

> [!note] Filter types
> Display filters control which captured packets are shown. Capture filters are set before capture and control which packets are collected; the two filter syntaxes differ.

## Protocol analysis

> [!note] Filter types
> Display filters are applied while viewing packets. Capture filters are set before capture and determine which packets are collected; the two filter syntaxes differ.

### DNS
Enter this display filter:

```text
dns
```

DNS packets show domain-name queries and responses. Inspect the query name and, when present, the IP address returned in the response.

### TCP
Enter this display filter:

```text
tcp
```

The TCP three-way handshake consists of a client SYN, a server SYN/ACK, and a client ACK.

Useful filters for the handshake:

```text
tcp.flags.syn == 1
tcp.flags.syn == 1 && tcp.flags.ack == 1
tcp.flags.ack == 1 && tcp.flags.syn == 0
```

TCP packet details include source and destination ports and flags such as SYN and ACK.

### TLS
Enter this display filter:

```text
tls
```

In older Wireshark versions, the filter may be `ssl`. Look for handshake messages such as **Client Hello** and **Server Hello**. TLS protects application data, so the payload is generally encrypted. The handshake messages vary between TLS versions.

![[images/practical-4-003.png]]
*TLS packets showing handshake and encrypted application data.*

### IP
For IPv4, enter:

```text
ip
```

For IPv6, enter:

```text
ipv6
```

Relevant fields include source and destination addresses, header length, total length, identification, flags, time to live (TTL), protocol, and checksum.

![[images/practical-4-004.png]]
*Filtered IP traffic and selected packet details.*

### ICMP
For ICMP over IPv4, enter:

```text
icmp
```

For ICMP over IPv6, enter:

```text
icmpv6
```

Relevant fields include type, code, checksum, identifier, sequence number, and data. A ping commonly produces Echo Request and Echo Reply packets.

![[images/practical-4-005.png]]

For your own capture, record the filter used, packet numbers, endpoints, relevant fields, and what the observation supports. Avoid claiming more than the packet data establishes; for example, a displayed DNS response or IP address alone does not identify the person using a host.

## Conclusion
> Wireshark can capture and inspect network traffic and display selected packets by protocol or field. DNS, IP, TCP, TLS, and ICMP observations help describe network communication when the capture context and limitations are recorded.
